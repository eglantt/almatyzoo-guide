# CLAUDE.md — Путеводитель по Алматинскому зоопарку (PWA)

Рабочая память проекта: правила работы, принятые решения, открытые вопросы и отложенные планы.
Обновляется по ходу каждой итерации.

---

## 1. Правила работы (обязательные)

1. **Код пишется только по команде заказчика.** Claude сообщает о готовности, описывает план и запрашивает разрешение. Без явной команды код не пишется. Правило действует на каждой итерации.
2. **Вопросы задаются порциями — не более 5 за раз.**
3. **Данные даёт заказчик.** Перечень животных, зон, координаты и тексты правил приходят от заказчика и вносятся поэтапно. Пометки «требует проверки» на данные заказчика не ставятся.
4. **Наполнение поэтапное.** Данные можно добавлять и актуализировать частями, без переделки структуры.
5. Все изменения фиксируются в `CHANGELOG.md`.
6. **Никаких обращений к GitHub и другим внешним сервисам без явного разрешения заказчика** — ни проверки подключения, ни запросов доступа, ни отправки файлов. Сначала объяснить, что и зачем будет сделано, дождаться команды.
7. **Материалы из других проектов заказчика (`docs/ref-*.md`) — образцы, а не готовые предписания.** Отталкиваться от них и делать своё с учётом функций и специфики этого приложения.
8. Раздел «Проверено» (наборы, число проверок, новые проверки, итоги снимков) ведётся в `CHANGELOG.md` у каждой версии.
9. **Демо для предварительной проверки.** Если функцию нужно проверить до встраивания в приложение — собирается демо. Делается **только по просьбе заказчика**. Порядок — раздел «Демо» ниже (образец — `docs/ref-sldt-demo.md`).

## 3а. Репозиторий и порядок работы с GitHub

- Репозиторий: **https://github.com/eglantt/almatyzoo-guide** (публичный, владелец — заказчик). Подключён к сессии Claude с правом записи.
- Ветка одна — `main`. До релиза приложением пользуются только заказчик и тестировщики.
- Каждая версия — коммит. **Метки (теги) из среды Claude не отправляются** — доступ к GitHub их не пропускает; метку и релиз с ZIP заказчик при желании ставит сам в браузере (Releases → Create a new release).
- **Любое действие с GitHub (отправка, метка, релиз, настройки) — только по команде заказчика**, после описания, что будет сделано.
- Перед отправкой кода Claude прогоняет тесты.
- GitHub Pages включается заказчиком после первой отправки кода (инструкция — в момент включения).
- Подтверждения действий в интерфейсе Claude — «Разрешить один раз» (второй замок поверх правила «только по команде»).
- Внешние сервисы данных (Overpass API OpenStreetMap и др.) из среды Claude недоступны.
- Локальная копия у заказчика — способ ещё выбирается (ZIP релиза / GitHub Desktop / ZIP в чат). Запуск локально — только через локальный сервер (Live Server или `python -m http.server`), не двойным щелчком.

## 6. Принятые решения

### Карта
- Leaflet подключается **локально** (`lib/`), не с CDN.
- Подложка — тайлы OSM, кэшируются по мере просмотра (массовая предзагрузка запрещена правилами OSM).
- Офлайн-основа — **векторные слои из data.json**: контур зоопарка, контуры павильонов и вольерных комплексов, маркеры. Работают без сети и без тайлов.
- Схема из печатного буклета **не используется** (стилизованная, косоугольная проекция, не совпадает с картой).
- Карта ограничена территорией зоопарка **с запасом**, чтобы были видны парковки и остановки общественного транспорта. Минимальный зум ~16.
- «Где я?» вне территории: синяя точка + сообщение «Вы вне территории зоопарка» + кнопка «К зоопарку».

### Координаты
- Заказчик снимает координаты в Google Maps (правый клик по точке → копирование координат).
- Формат передачи: «название — широта, долгота». Для контуров — точки по углам в порядке обхода по часовой стрелке.
- До получения реальных координат используются ориентировочные с флагом `"approx": true` в data.json.

### Коллекция (этап 1)
- На старте — зоны отделов, павильоны, вольерные комплексы и крупные вольеры. Ориентировочный перечень: хищные птицы, водоплавающие птицы, копытные, павильон «Аквариум», дом птиц, павильон «Экзотариум», зебры, кенгуру, бегемоты, крокодилы, слоны, носороги, приматы, жирафы, белый медведь, медведи, львы, дом хищников.
- Полный перечень коллекции заказчик передаст позже.
- **Фотографии животных не используются.** Люди приходят смотреть животных вживую. Вместо фото — стилизованные иконки в стиле инфографики.

### Карта при открытии
- Всегда показывается вся территория зоопарка; «Где я?» — по нажатию.

### Попап места
- Состав на усмотрение Claude, доработка по итогам просмотра. Стартовый вариант: название, краткое описание, собственные часы (если есть), санитарный день, расстояние, кнопка «Показать в коллекции».

### Зоны
Зоны называются по-разному, единой схемы нет:
- **по группам животных:** фазаний ряд, хищные птицы, копытные;
- **по локациям:** пруд;
- **по большим вольерам:** белый медведь, слон, бегемот, полярные волки, тигры;
- **по павильонам:** Аквариум, Экзотариум, Дом птиц, Приматы, Дом хищников.

Это и есть разделы коллекции (перечень может уточняться вместе с полной коллекцией).
**Служебные зоны** (только служебный слой): хоздвор, ветеринарная часть, виварий, склады.

### Структура данных: места и обитатели (принято)
- **Места** (`places`) — точки и контуры на карте: павильоны, вольеры, инфраструктура. Имеют координаты.
- **Обитатели** (`animals`) — виды из коллекции. Координат нет, есть ссылка на место (`placeId`).
- Пример масштаба: в «Экзотариуме» живёт 70+ видов, экспонируется около 40+. Структура рассчитана на десятки видов в одном месте; в коллекции показываются экспонируемые виды.

### Инфраструктура (типы объектов)
Центральный вход, другие входы, служебный вход, касса, охрана, кафе, торговые ларьки, туалеты, медпункт, беседки, детская площадка, парковка, остановки общественного транспорта, информация.
**Нет на территории:** банкомат, зоны отдыха.

### Контакты, адрес, часы
- Адрес: г. Алматы, ул. Есенберлина, 166.
- Без выходных. Часы зависят от сезона:
  - лето — зоопарк 9:00–20:00, кассы 9:00–19:00;
  - зима — зоопарк 9:00–18:00, кассы 9:00–17:00.
- **Переключение сезона — автоматическое, по датам.** Ручное переключение не используется (приложение — путеводитель для посетителей). Даты перехода заказчик уточнит позже; до этого — временные даты-заглушки в data.json.
- Цены не публикуются в приложении — ссылка на сайт almatyzoo.kz.
- На сайте указаны санитарные дни: вторник — «Экзотариум», четверг — «Дом птиц» (уточнить актуальность).
- **Телефон с сайта не актуален (не работает).** Актуальный номер, WhatsApp и ссылки на соцсети заказчик передаст позже. В 0.1.0 — места под них в data.json. Email: info@almatyzoo.kz.

### Как добраться
- Кнопки 2GIS / Google Maps / Яндекс ведут **по координатам к центральному входу**, а не по адресу.
- **Общественный транспорт:** автобус № 60. Большинство посетителей едут до парка культуры рядом с зоопарком и идут к зоопарку пешком через парк — показать этот путь как рекомендуемый.
- **Парковка для посетителей** есть, но в сезон всегда забита — показать на карте с предупреждением «в сезон часто нет мест» и подсказкой про общественный транспорт.

### Кнопка «К выходу»
- Для посетителей, которые теряются на территории: прокладка маршрута от текущего местоположения до центрального входа.
- **Этап 1 (0.1.0):** линия от пользователя до выхода, расстояние в метрах, стрелка-направление.
- **Этап 2:** полноценный маршрут по дорожкам, офлайн — после сбора треков дорожек.
- Режима ЧС для посетителей пока нет.

### «Найти рядом» (быстрый доступ на карте)
- Всплывающее меню-«аккордеон» на карте: **Туалет · Кафе · Медпункт · Выход**.
- Выбор показывает ближайший объект и расстояние; пункт «Выход» = кнопка «К выходу».

### Расстояния
- В попапе — расстояние до объекта (≈ 120 м) и, возможно, время пешком (≈ 2 мин). Окончательно — по визуальной проверке.

### Потерявшийся ребёнок
- Блок «Если потерялся ребёнок» в разделе помощи: обращаться к **охране** (оперативно передают по рации остальным), телефон, кнопка «Показать на карте».

### Принцип простоты
- Для посетителей — максимально простой и интуитивный функционал, без перегрузки функциями.
- Отдельного переключателя «Крупный текст» нет. Размеры задаются в относительных единицах, чтобы учитывалась системная настройка размера шрифта телефона. Решение пересматривается по итогам тестов.

### О зоопарке — программы
Волонтёрство, Зоошкола, Экскурсии (по 1–2 строки + ссылка на страницу сайта). Список может быть дополнен.

### Тестирование
- Тесты заводим и прогоняем при каждом изменении — по образцу SLDT (см. раздел «Тесты»).
- Уведомление о сборе обезличенной статистики — решим позже.

### Зимники, сезонные и закрытые объекты (решено 10.11.2026, версия 0.1.2)
- **Два положения у каждой зоны коллекции — летнее и зимнее.** Варианты зимнего:
  - остаётся на месте (круглый год в одном вольере);
  - переезжает в **экспонируемый зимник** — зимой маркер у зимника, в попапе «Зимний вольер»;
  - **зимник не экспонируется** — зимой маркера нет, в коллекции «Зимой не экспонируется, вернётся весной».
- **Даты перевода — свои у каждой зоны** (не совпадают с летним/зимним режимом зоопарка). Переключение автоматическое по датам.
- Зимники — отдельные места на карте, отмечаются полевым режимом.
- Список переездов и экспонируемых зимников — от заказчика позже, вместе с коллекцией. До этого все зоны «остаются на месте».
- **Служебные вход, въезд, парковка** — в `service` data.json: посетителям не показываются, в полевом режиме доступны для привязки точек (0.1.3).
- **Закрытие павильона или вольера** — иконка остаётся, в попапе и коллекции «Временно закрыт · причина, до ДД.ММ» (0.1.3, предложение Claude).
- **Ларьки и туалеты:** пометка «работает только летом» — зимой иконка скрыта; **временное закрытие** «с — по» с причиной (ремонт) — на это время иконка скрыта, потом возвращается сама. До админпанели закрытия вносит Claude в data.json по сообщению заказчика.
- **Закрытые объекты не участвуют в «Найти рядом».**
- **Границы вольеров** — полевой режим → «Контур» → выбрать место; приложение рисует контур места на карте.

### Данные OpenStreetMap (внесено в 0.1.3)
- Граница зоопарка и дорожки — из OSM (файл заказчика с overpass-turbo, 09.11.2026), перенесены в data.json (`meta.boundary`, `paths`), дорожки обрезаны по контуру. Площадь контура 21,4 га. Атрибуция «© OpenStreetMap» видна при любой подложке.
- **Все дорожки — одинаково**, служебные проезды не выделяются: дорожки не относятся к служебной инфраструктуре (решение заказчика 10.11.2026). Недостающие дорожки заказчик дорисует полевым режимом.
- **Центральный вход — на западной стороне контура** (подтверждено заказчиком), у пешеходной площадки с лестницей.
- Места, оказавшиеся за контуром, сдвинуты внутрь ориентировочно (approx) — до координат из полевого режима.
- **Переключатель «Схема / Спутник» — в обычном и в полевом режиме** (решено 10.11.2026, версия 0.1.3). По умолчанию: обычный режим — схема, полевой — спутник. Выбор запоминается отдельно для каждого режима. Оба слоя кэшируются для офлайна.
- ⚠️ **К публичному релизу:** сверить условия Esri для спутниковых снимков в публичном приложении. Если ограничено — в обычном режиме спутник убрать, в полевом оставить.

### Входы и въезды
Находятся в разных точках периметра.
- **Центральный вход** — для посетителей, там же касса. Единственный вход, показываемый посетителям.
- **Служебный вход** — только для персонала → служебный слой.
- **Служебная парковка** — только для персонала → служебный слой.
- **Служебный въезд** — только для техники (грузовой, строительной, специальной) → служебный слой.

### Язык при первом запуске
Вариант Б: экран с тремя крупными кнопками «Қазақша / Русский / English», язык устройства подсвечен; выбор одним тапом, экран больше не появляется. Переключатель в шапке доступен всегда. (Резервный вариант В: автоопределение + подсказка у переключателя.)

- «Показать на карте» / «Показать в коллекции» переключают вкладку и подсвечивают объект.

### Заставка
- В 0.1.0 — только нативный сплэш PWA (из manifest).
- Позже — анимированная заставка с логотипом, плавно переходящая в экран выбора языка (одобрено как направление; эффект выберем отдельно).

### Оформление
- **Шрифт:** см. раздел «Шрифты — по образцу SLDT».
- **Тема:** только светлая высококонтрастная, тёмной нет.
- **Установка и обновления:** кнопка «Установить приложение» в разделе «Ещё» (на iPhone — короткая инструкция «Поделиться → На экран „Домой“»). Обновление — автоматическое (см. «Версия и обновления»).
- **Иконки маркеров:** предварительно — круглый маркер, цвет по типу объекта, белая пиктограмма. Окончательный выбор — по отдельным файлам-образцам, визуально.
- **Все иконки (маркеры, интерфейс, правила, PWA-иконки) показываются заказчику на согласование до использования в приложении.** Порядок: сначала 2–3 варианта стиля на нескольких иконках → выбор стиля → полный набор на листе-образце → утверждение → только потом в приложение.

### Адаптивность
- Интерфейс адаптивный для всех ширин экрана: телефоны, планшеты, **десктоп (ПК)**.
- **Единая компоновка на всех устройствах.** Приложение заточено под смартфоны; на ПК интерфейс просто растягивается по ширине. Компоновка не меняется: шапка, экран, нижнее меню — везде одинаково. Боковых панелей и отдельной десктопной раскладки нет.

### Поиск
- По всем трём языкам одновременно, независимо от выбранного языка интерфейса.
- Без учёта регистра и пар ё/е, і/и, ү/у и подобных; частичные совпадения; результаты сгруппированы «Животные» / «Объекты».

### Часы павильонов
- У места может быть собственный режим работы; если не задан — действуют общие часы зоопарка.
- «Экзотариум» — 10:00–18:00. «Дом птиц» — уточняется.

### Сервисная панель разработчика (входит в 0.1.0)
- Вход: **7 тапов по номеру версии** → ввод пароля.
- На этапе персонального тестирования пароль `12345`. Проверка — по схеме SLDT с PBKDF2 (см. ниже). ⚠️ К релизу — длинный ключ.
- Состав: версия приложения и данных; состояние Service Worker и кэша, «Очистить кэш и перезагрузить»; GPS и точность; подсветка точек `approx`; подмена даты и местоположения; сброс языка; журнал ошибок с отправкой; полевой режим.
- **Полевой режим (сбор координат):**
  - данные хранятся в localStorage;
  - карта в полевом режиме — со слоем спутниковых снимков;
  - точки, контуры и **треки** (запись маршрута при прохождении пешком);
  - кнопка «Экспорт» — **только в сервисной панели**; имя файла содержит дату и время (например `zoo-points_2026-11-06_14-30.geojson`);
  - точка/контур привязываются к месту из data.json (0.1.1); контур — «Шаг назад», перетаскивание точек, «Изменить» сохранённый (0.1.2);
  - пиктограммы мест перетаскиваются, одна запись на место (0.1.2);
  - в полевом режиме плашка и кнопки посетителя скрыты (0.1.2).
- **Плашка:** одна строка, крестик скрывает до конца дня (0.1.2).

### Автообновление и ключ панели — по образцу SLDT (принято)
Источник: `docs/ref-sldt-update-and-key-gate.md` (проект заказчика SLDT 7.4.5, проверено в работе).

**Берём как есть:**
- регистрация SW с `updateViaCache: 'none'`, `reg.update()` при загрузке и при возврате в приложение (`visibilitychange`);
- `hadController` + флаг `refreshing` — одна перезагрузка, без перезагрузки при первой установке;
- `install` с `cache: 'reload'` + `skipWaiting`, `activate` с удалением старых кэшей + `clients.claim`;
- страница «сначала сеть» с таймаутом 3,5 с, запоздавший ответ ложится в кэш; остальное «сначала кэш»;
- два кэша: `app-<версия>` (каркас) и `assets-<версия ресурсов>` (тяжёлое, докачка в фоне один раз, из навигации).

**Адаптация под наш проект:**
- В каркас (`CORE_FILES`) входят: index.html, styles.css, app.js, data.json, manifest.json, Leaflet (js+css), PWA-иконки. Иконки маркеров — в assets.
- **Третий кэш — тайлы карты** (OSM; спутник — для полевого режима): чужой домен, «сначала кэш», с ограничением числа тайлов. В SLDT чужие домены не обрабатываются — у нас обработчик добавляется.
- **Google Таблица** (оперативные данные): «сначала сеть», при сбое — последняя полученная копия.
- **Отложенная перезагрузка:** если идёт запись трека в полевом режиме или в админпанели есть несохранённые изменения — перезагрузка откладывается до их завершения.
- Ранее предложенное ограничение «перезагрузка только в первые секунды после запуска» снято — схема SLDT проверена на практике.
- **Один номер версии:** версия в `sw.js` и в приложении должны совпадать — проверяется автотестом (защита от забытой смены `CACHE_VERSION`).

**Ключ сервисной панели:**
- 7 тапов по номеру версии; окно задано константой — **3 секунды** (в SLDT 2 с).
- Обработчик на постоянном родителе; тап по фону окно не закрывает; Enter = «Подтвердить»; ошибка — поле очищается.
- Проверка: **PBKDF2** (`crypto.subtle`), в коде только соль и хэш; флаг авторизации — внутри модуля, не глобальный.
- Это «замок от случайного входа», не защита: обходится из консоли браузера. Пароль `12345` на этапе тестов подбирается мгновенно даже по хэшу — **к релизу длинный ключ (16+ символов или 4–5 слов)**.
- **Админпанель контента защищена по-настоящему:** пароли редактора и админа проверяет Google Apps Script на стороне Google; их хэшей в коде приложения нет.
- Блоки панели в коде помечаются маркерами `ZOO:SYS-TOOLS:START/END`.

### Шрифты — по образцу SLDT (принято)
Источник: `docs/ref-sldt-fonts-offline.md`. Решение «системный шрифт» отменено.

- Шрифты — **файлы самого приложения** в папке `fonts/`, woff2, пути относительные. **Никаких внешних сервисов шрифтов** нигде, включая Service Worker.
- Источник файлов — npm-пакеты Fontsource (`@fontsource/…`), лицензия SIL OFL 1.1; тексты лицензий лежат в `fonts/`.
- Только нужные начертания и алфавиты; у каждого `@font-face` — `unicode-range` и `font-display: swap`.
- **Алфавиты проекта:** латиница, кириллица **и cyrillic-ext** — в нём казахские буквы ә ғ қ ң ө ұ ү һ (і — в основной кириллице).
- **До подключения — проверка покрытия по самому файлу шрифта** (fontTools), не по скриншоту: все буквы трёх языков (строчные и заглавные), цифры, знаки проекта: « » — – № ≈ ° · → ₸. Чего нет — цепочка шрифтов или замена знака.
- Если тому же шрифту нужно другое начертание для другой роли — отдельное имя семейства.
- В Service Worker шрифты — в `ASSET_FILES` (кэш ресурсов), не в каркасе; «сначала кэш».
- Выбор шрифта — визуально, по листу-образцу с текстами приложения на трёх языках; казахские буквы дополнительно оценивает носитель языка.
- Проверка готовой версии: в сети ни одного запроса к чужим доменам за шрифтами; в авиарежиме шрифты те же.

### Тесты — по образцу SLDT (принято)
Источник: `docs/ref-sldt-testing.md`. Два слоя, оба обязательны.

**Слой 1 — автотесты в Node** (папка `tests/` в репозитории, `npm test`, единственная зависимость — jsdom; `node_modules` не коммитится; SW папку `tests/` не кэширует).
- Тест открывает **настоящий** `index.html` в jsdom и действует как пользователь; каждый сценарий — с чистого запуска.
- Заглушки: `fetch` (отдаёт настоящий data.json проекта), **геолокация** (подставные координаты: у входа, в глубине, вне территории, без разрешения), хранилище, часы.
- **Подмена часов** — для сезонов, часов павильонов, санитарных дней, позже — блока «Когда показывать».
- **Режимы проекта = три языка** (аналог двух тем SLDT): наборы, проверяющие интерфейс, прогоняются на kz, ru и en.
- Leaflet в jsdom не имеет размеров: проверяется состав слоёв, маркеры, фильтры, содержимое попапов; всё видимое — в слое 2.

**Предварительные наборы:**
| Набор | Что проверяет |
|---|---|
| app | запуск без ошибок, выбор языка, переключение языка, меню, поиск, связи карта ↔ коллекция, правила, раздел «Ещё» |
| schedule | лето/зима, часы павильонов, санитарные дни, «Сегодня закрыт» — с подменой часов; сочетания попарно |
| geo | «Где я?», «Вне территории», «Найти рядом», «К выходу», расстояния |
| panel | 7 тапов, ключ, подмены даты и GPS, полевой режим (точки, контуры, треки, экспорт, имя файла), отложенная перезагрузка |
| data | data.json: три языка, уникальные id, ссылки обитатель → место, координаты в границах |
| fonts | **каждый символ из data.json и интерфейса есть в файлах шрифта**; нет ссылок на внешние сервисы шрифтов |
| sw | Service Worker в песочнице `vm`: каркас, 404, офлайн, таймаут, докачка, кэш тайлов, старые кэши |
| version | версия совпадает во всех местах, включая кэш SW |

**Слой 2 — настоящий Chromium (Playwright).**
- Снимки на ширине **360 и 393** + **десктоп** (единая компоновка — проверить растяжение), на **трёх языках** (казахские строки длиннее — переполнение кнопок и меню).
- Перед съёмкой: часы зафиксированы, анимации выключены, геолокация задана.
- Попиксельное сравнение с предыдущей версией.
- Замеры на процессоре, замедленном в 6 раз, — для анимаций и скорости запуска.
- Ограничение окружения Claude: тайлы OSM из песочницы не грузятся — на снимках карта без подложки (векторные слои и маркеры видны). Подложку проверяет заказчик на телефоне.

**Правила:**
- Объём проверки по типу изменения: косметика — снимки + сверка + затронутый набор; логика — все наборы + снимки.
- Наборы — **по одному**, не параллельно.
- Новая проверка должна **падать на прошлой версии**; не допускать проверок, проходящих вхолостую; проверять поведение, а не текст кода.
- Упавшую старую проверку не ослаблять, пока не ясно — ошибка это или намеренное изменение.
- Порядок перед выпуском: правка → новые проверки → наборы (0 FAIL) → снимки → версия во всех местах → раздел «Проверено» в CHANGELOG (наборы, число проверок, новые, итоги снимков) → отправка по команде.
- Исходник всегда — репозиторий GitHub (рабочее пространство Claude может пропасть). jsdom ставится заново из npm — по разрешению заказчика.
- Ручная проверка на телефонах заказчика (iPhone, Android, Samsung, Huawei, Xiaomi) — дополнение к двум слоям, не замена.

### Демо и листы-образцы — по образцу SLDT (принято)
Источник: `docs/ref-sldt-demo.md`.

**Два вида страниц для выбора:**
- **Лист-образец** — статичные варианты рядом (шрифты, иконки, цвета). Своя нумерация: лист-образец №1, №2… Публикуется ссылкой-страницей Claude (открывается на телефоне и ПК).
- **Демо** — живая страница с панелью переключателей, где заказчик сам смотрит и выбирает вид или поведение. Сквозная нумерация: **следующее демо — №1**. Доработка того же демо — дробный номер (1 → 1.2 → 1.3). Файл `demo/demo_<N>_<english_name>.html`, в заголовке и панели — номер и название по-русски.

**Когда:** только по просьбе заказчика; когда решение зависит от того, как выглядит или ощущается. Логические вопросы решаются словами, мелочи — снимками 2–3 вариантов. Выбор в демо — решение о виде, **не разрешение на код**.

**Устройство демо:**
- Внутри — **настоящий код текущей версии приложения** (после выхода 0.1.0); до 0.1.0 демо собирается на том же стеке, данных и шрифтах, что пойдут в приложение.
- Своё хранилище (ключи с приставкой `zoo_demo<N>_`), настоящие данные пользователя не трогаются.
- **Выключено всё внешнее:** Service Worker, запись в Google Таблицу / Apps Script, статистика, отправка в WhatsApp.
- Панель настроек (на ПК ~370 px сбоку, на телефоне сверху), приложение в рамке экрана телефона, подпись «393 × 800 · показано в 87%».
- Вместо двух тем SLDT — **выбор языка kz / ru / en**; выбор ширины 320 / 360 / 393 / 430 / 768 / ПК; «вписать» / «1 : 1».
- Каждая настройка — карточка: название, текущее значение, 1–2 строки пояснения, варианты кнопками (числа — ползунком в секундах, пикселях, процентах), под выбранным — что именно он делает. Неактивная настройка тускнеет с пометкой «сейчас не действует».
- Обязательный вариант **«Как сейчас»** и кнопка «Всё как сейчас»; по умолчанию — «как сейчас» или предложение Claude, с пометкой, что именно.
- Свои добавки Claude отмечаются явно.
- **Сценарии «▶ …»** под путеводитель: подставные место (у входа, в глубине, у пруда, вне территории, без GPS) и время (лето/зима, санитарный день, вечер перед закрытием).
- Блок **«Сборка»**: выбор словами + «Скопировать сборку»; выбор запоминается в браузере (try/catch); «Сбросить демо-сохранение».

**Где живёт демо — ограничение среды:** страница-ссылка Claude не загружает тайлы карты с чужих сайтов и не даёт геолокацию. Поэтому:
- демо без карты и GPS — страницей-ссылкой Claude;
- **демо с картой, GPS, кэшем или скоростью — в репозитории в папке `demo/`** (открывается через GitHub Pages тем же путём, что и приложение). Папка `demo/` не кэшируется SW и не входит в архив версии. Отправка — по команде заказчика.

**Проверка перед выдачей:** снимки в Chromium (360 и 393, три языка, основные варианты), каждый сценарий проигран, «как сейчас» совпадает с приложением, хранилище приложения не тронуто, внешние отправки не произошли.

**После выбора:** сборка заказчика записывается дословно в CHANGELOG будущей версии («Выбор заказчика (демо N): …», со всеми числами, с историей изменений выбора) → план → команда на код → в приложение переносится **только выбранное** и ровно как в демо → сверка приложения с демо по каждой части.

## 8а. Редактируемый контент через Google Таблицы (принято; версия — предложено 0.1.x сразу после 0.1.0, ждёт подтверждения)

**Идея заказчика:** актуальные контакты, акции и сообщения пользователям редактируются без выпуска новой версии. До релиза — через Google Таблицы, после переезда на хостинг зоопарка способ меняется.

**Предложение Claude:**
- **Разделение данных.** Постоянное (карта, места, коллекция, правила) — в `data.json`, меняется через версии. Оперативное (контакты, соцсети, акции, объявления, даты сезонов, временные закрытия) — в Google Таблице.
- **Чтение:** таблица публикуется в интернете (CSV), приложение читает её без ключей. Данные в опубликованной таблице публичны — подходит только для открытой информации.
- **Офлайн:** приложение запоминает последние полученные данные; без сети показывает их. Если таблица недоступна или испорчена — запасные значения из `data.json`.
- **Защита от ошибок:** строки с битыми данными пропускаются, остальное работает. Задержка публикации Google — до ~5 минут.
- **Решено: редактирование только через админпанель в приложении.** Правка таблиц напрямую неудобна. Редактируют несколько сотрудников.
- **Схема:** посетители читают опубликованную таблицу (быстро, без лимитов, выдерживает наплыв). Админпанель записывает через Google Apps Script (веб-приложение) — он же проверяет логин и пароль на стороне Google, не в коде приложения.
- **Учётные записи: две общие** — один админский доступ и один редакторский (решение заказчика). Пароли хранятся как хэш с солью на стороне Apps Script. Сессия с ограниченным сроком.
  - **Редактор** — вносит и правит информацию.
  - **Администратор** — всё то же + смена пароля редактора (например, при уходе сотрудника) и просмотр журнала.
- **Журнал изменений:** когда, под какой ролью и что изменено (старое → новое значение) — отдельный лист. Позволяет откатить ошибку. Конкретного человека журнал не различает (общие доступы).
- **Вход:** та же скрытая точка — тапы по номеру версии; после входа доступно то, что разрешено роли (единый вход для разработчика, админов контента, позже персонала и охраны).
- Сохранение требует сети; без сети админпанель показывает предупреждение.
- **Предпросмотр обязателен:** перед публикацией изменение показывается так, как его увидит посетитель; публикуется только кнопкой «Опубликовать».
- **Аккаунт Google:** пока личный аккаунт заказчика, позже перенос на аккаунт зоопарка.
- **Чтение и запись делаются одним блоком** (таблица + Apps Script + админпанель + предпросмотр): читать нечего, пока нечем вносить.
- Стартовую структуру таблицы и начальное наполнение готовит Claude (файл для импорта), чтобы таблица не была пустой.

**Что правится через админпанель:**
| Раздел | Кто | Особенности |
|---|---|---|
| Контакты, соцсети, ссылка на сайт | редактор, админ | Ссылки на сайт и соцсети в целом, не на отдельные новости |
| Сообщения пользователям / акции | редактор, админ | Тексты kz/ru/en, даты показа «с — по», тип |
| Мероприятия | редактор, админ | **Включаются и отключаются** переключателем; постоянно не висят |
| Расписание кормлений | редактор, админ | **Включается и отключается** переключателем; постоянно не висит |
| Часы работы (общие, кассы, павильоны), даты сезонов | редактор, админ | |
| Санитарные дни | редактор, админ | |
| Экстренное объявление | **только админ** | Заметная плашка поверх всего (напр. «Зоопарк сегодня закрыт») |
| Временные закрытия павильонов и вольеров | редактор, админ | «Закрыт на ремонт», «карантин» и т.п. |

**Не делаем:** новости в приложении (люди узнают их на сайте и в соцсетях).

**Единый блок «Когда показывать»** — один и тот же для мероприятий, кормлений, сообщений, акций и временных закрытий (максимально гибко, по решению заказчика):
- **Вкл/выкл** — главный переключатель, действует всегда;
- **Период** «с — по» (необязательно) — по окончании запись скрывается сама;
- **Повтор:** однократно / ежедневно / по дням недели;
- **Время:** одно или несколько (кормление в 11:00 и 15:00);
- **Сезон:** круглый год / лето / зима;
- **Даты-исключения** — дни, когда не проводится;
- **Привязка к месту на карте** (необязательно) — показывается в попапе места, кнопка «Показать на карте».

В админпанели основные поля видны сразу, расширенные (повторы, исключения, сезон) — под «Дополнительно», чтобы простые записи вносились быстро.
- **Сообщения пользователям:** текст на kz/ru/en, даты показа «с — по», тип (инфо / важно / акция); показываются плашкой, закрываются крестиком.
- **Переезд:** чтение данных вынесено в один модуль («источник данных»); при переезде на хостинг зоопарка меняется только он.
- Таблица и Apps Script — пока на аккаунте заказчика, позже перенос на аккаунт зоопарка.

## 9. Служебный режим (отложено, проектирование)

**Назначение:** функции для персонала и охраны, которые не показываются посетителям.
**Конфиденциальных данных нет.** Утечка пароля раскрывает только расположение служебных объектов. Поэтому шифрование данных не требуется: достаточно скрытого входа и паролей групп (в коде хранятся только хэши паролей).

**Вход:** несколько тапов по неочевидному элементу на одной из страниц → панель ввода пароля. Пароль определяет группу и уровень доступа.

**Функции по группам (предварительно):**
1. **Статистика использования приложения** — данные собираются в Google-таблицу и показываются оттуда. Статистика обезличенная, без персональных данных посетителей. Отправка требует сети; офлайн события копятся в очереди и отправляются при появлении связи.
2. **Заметки с геолокацией** — хранятся локально на устройстве, текст отправляется в рабочий чат WhatsApp.
3. **Расширенная карта (персонал и охрана)** — служебные объекты: служебный вход, служебная парковка, служебный въезд для техники, гараж, виварий, кормокухня, хоздвор, склады, бытовки, колонки, пожарные щиты и гидранты, служебные входы в павильоны, маршруты проезда габаритной техники, канализационные колодцы, урны, мусорные контейнеры и т.п.
4. **Сетка / зоны для охраны** — разбивка карты на именованные зоны или квадраты, чтобы по рации быстро сообщить место происшествия, своё местоположение при обходе, запросить помощь.

**Технические заметки:**
- Отправка текста в групповой чат WhatsApp из веб-приложения напрямую невозможна (ссылка wa.me работает только на номер). Решение: кнопка открывает WhatsApp с готовым текстом, сотрудник выбирает рабочий чат (одно касание).
- Структура data.json в 0.1.0 закладывается так, чтобы служебный слой добавлялся без переделки.
