# Технология из проекта SLDT (PWA на GitHub Pages): шрифты без интернета

Описание сверено с SLDT версии 7.4.5. Здесь не про то, какие шрифты выбраны, а про то, как они подключены: приложение никогда не обращается за шрифтами к внешним сайтам и после первого открытия показывает их без сети.

---

## 1. Главный принцип: шрифты — это файлы самого приложения

- Файлы шрифтов лежат в папке `fonts` рядом с главной страницей, в том же репозитории и на том же сайте. Формат — woff2 (самый компактный, его понимают все современные браузеры).
- Нигде в проекте нет ссылок на Google Fonts или другие внешние сервисы шрифтов: ни в разметке страницы, ни в стилях, ни в сервис-воркере.
- Страница сама объявляет каждый шрифт в своих стилях (правило `@font-face`) и указывает путь к файлу **относительно себя** (`fonts/имя-файла.woff2`, без адреса сайта в начале). Поэтому всё работает и на GitHub Pages, где сайт живёт в подпапке репозитория, и при локальном запуске.

### Почему не Google Fonts
Так было в SLDT до версии 5.9.108, и это давало две проблемы:
- **без сети** интерфейс оставался в системном шрифте телефона;
- **при появлении сети** текст «прыгал», когда шрифт догружался.

Для приложения, которое заявлено как работающее офлайн, это неприемлемо.

### Где брать файлы
Если прямого доступа к Google Fonts нет (в рабочем окружении Claude его нет), те же самые файлы есть в npm-пакетах Fontsource (`@fontsource/имя-шрифта`). В них лежат подлинные woff2, уже разрезанные по алфавитам и начертаниям.

Лицензия у таких шрифтов — SIL Open Font License 1.1: она разрешает встраивать шрифт в приложение. Текст лицензии каждого шрифта кладётся в ту же папку `fonts`.

## 2. Брать только нужное: начертания и алфавиты

Шрифт в Fontsource разрезан на отдельные файлы: по начертанию (400 — обычный, 500 — средний, 700 — жирный) и по алфавиту (латиница, кириллица и т.д.). В SLDT взяты только те, что реально используются:
- 9 файлов;
- около 95 КБ вместе.

Целиком шрифт со всеми начертаниями и алфавитами весил бы в разы больше.

Каждый файл — отдельное объявление `@font-face` с тем же названием семейства, но своим начертанием. Браузер скачивает файл только тогда, когда на странице действительно есть текст в этом начертании.

### Разделение по алфавиту (`unicode-range`)
Для шрифта, у которого латиница и кириллица в разных файлах, в каждом объявлении указан диапазон символов, которые этот файл покрывает. Для кириллицы — диапазон русских букв, для латиницы — латинские буквы, цифры и основные знаки.

Браузер сам решает, какой файл нужен для конкретного текста. Если на экране только русский текст, латинский файл даже не скачивается.

### Обязательно проверить, есть ли в шрифте нужные буквы
Это главный урок SLDT, на нём проект ошибся дважды:
- **Orbitron** (основной стилизованный шрифт) не содержит **ни одной** русской буквы. Весь русский текст «в Orbitron» с самого начала проекта на деле показывался системным шрифтом телефона. Заметили только при обсуждении смены шрифта.
- **Roboto Mono** в проекте — тоже только латиница. Русский текст в нём уходил в системный моноширинный шрифт телефона. Он выглядит по-разному на разных устройствах и никак не управляется.

Перед подключением шрифта нужно проверить, что в нём есть все алфавиты проекта, а также нужные значки: стрелки, валютные и прочие специальные символы. Символ, которого нет ни в одном шрифте проекта, браузер возьмёт из системы, и на разных телефонах он будет выглядеть по-разному. В SLDT так было со значком кредитов, его пришлось заменить.

## 3. Цепочка шрифтов: каждый символ — из того шрифта, который его умеет

Если стилизованный шрифт хорош для цифр и латиницы, но не имеет кириллицы, его не нужно выбрасывать. В SLDT у заголовков и кнопок указана **цепочка**: сначала Orbitron, затем Exo 2 (близкий по стилю, геометричный, с кириллицей), затем системный шрифт как последний запасной.

Браузер выбирает шрифт **для каждого символа отдельно**:
- цифры и латиница берутся из первого шрифта;
- русские буквы — из второго;
- то, чего нет ни в одном, — из системного.

Вручную размечать, где какой текст, не нужно.

### Отдельное название семейства для основного текста
Для основного текста (описания, журнал, окна подтверждения) понадобился тот же Exo 2, но в обычном начертании 400. Заголовки при этом используют среднее 500.

Если добавить начертание 400 под тем же названием «Exo 2», заголовки начнут подхватывать его вместо 500 и станут тоньше. Поэтому начертания для текста объявлены под **отдельным названием** («Exo 2 Text»). Это два независимых набора, и они не мешают друг другу.

### Разница в размере
Разные шрифты при одном и том же размере выглядят по-разному крупно. Когда текст переводили с моноширинного шрифта на Exo 2, размер пришлось увеличить примерно на 8%, чтобы визуально ничего не уменьшилось. Подбиралось по примеркам на экране.

## 4. Поведение при загрузке (`font-display: swap`)

У каждого объявления шрифта стоит режим «показать текст сразу, шрифт подменить, когда загрузится». Текст никогда не бывает невидимым в ожидании шрифта.

- В первый раз и в сети подмена может быть заметна долю секунды.
- Потом шрифт уже лежит в кэше телефона, и подмена происходит мгновенно, незаметно для глаза.

## 5. Кэширование сервис-воркером

Шрифты — часть офлайн-кэша приложения. Устройство кэша описано в соседнем документе про обновление, здесь только то, что касается шрифтов.

- Файлы шрифтов записаны в список тяжёлых файлов (`ASSET_FILES`) и хранятся в отдельном кэше картинок и шрифтов. Его версия (`ASSETS_VERSION`) меняется только когда меняется **содержимое** уже существующего файла.
- Поэтому обычное обновление приложения шрифты заново не скачивает.
- При первом открытии они скачиваются двумя путями, что сработает раньше:
  - когда страница впервые их запросила;
  - фоновой докачкой, по одному файлу.
- Для шрифтов действует правило «сначала кэш»: если файл уже есть в кэше, сеть не трогается вообще.
- Шрифтов **нет** в обязательном каркасе, который ставится при установке. Каркас должен оставаться маленьким, а шрифт, не успевший докачаться, всё равно подхватится при первом показе.

**Итог:** после первого открытия в сети приложение показывает все свои шрифты без интернета. Если какой-то файл ещё не успел скачаться, на это время виден системный шрифт, а не пустое место.

### Почему важно, что шрифты лежат на своём сайте
Сервис-воркер SLDT обрабатывает только запросы к своему же сайту. Запросы к чужим сайтам он пропускает мимо себя. Шрифт с внешнего сайта:
- не попадёт в офлайн-кэш;
- даже при особой настройке пришёл бы «непрозрачным» ответом, у которого нельзя проверить, успешно ли он загрузился.

Свои файлы этих проблем не имеют.

### Урок: убирать хвосты в сервис-воркере
Когда в SLDT шрифты перенесли в проект, страница перестала обращаться к Google. Но в сервис-воркере остались:
- отдельный кэш под шрифты Google;
- **настоящий запрос к Google при каждой установке**;
- две ветки обработки запросов, до которых код больше никогда не доходил.

Это нашли только при стороннем разборе и убрали. Старый кэш у пользователей удалился сам при следующем обновлении, потому что при активации сервис-воркер удаляет все кэши, кроме двух текущих.

## 6. Правила для нового проекта

1. Шрифты — только файлами в папке проекта, пути относительные, никаких внешних ссылок на шрифты нигде, включая сервис-воркер.
2. Брать только нужные начертания и алфавиты. Для разделённых по алфавиту файлов указывать диапазон символов.
3. До подключения проверить, что в шрифте есть все буквы и значки проекта. Если нет — цепочка шрифтов, где следующий покрывает недостающее.
4. Когда тому же шрифту нужно другое начертание для другой роли — отдельное название семейства.
5. Режим «показать текст сразу» у каждого объявления.
6. Каждый файл шрифта — в список офлайн-кэша. Новый файл — просто добавить в список. Изменилось содержимое существующего — поднять версию кэша картинок и шрифтов.
7. Положить тексты лицензий рядом со шрифтами.

### Как проверить, что всё правильно
- **Сеть.** В инструментах разработчика браузера, на вкладке сети, открыть приложение. Не должно быть ни одного запроса к чужим доменам: ни `fonts.googleapis.com`, ни `fonts.gstatic.com`, ни других. Все шрифты приходят с того же сайта.
- **Офлайн.** После одного открытия в сети включить авиарежим или «офлайн» в инструментах разработчика и перезагрузить. Шрифты должны остаться те же.
- **Буквы.** Смотреть не только латиницу, но и русский текст, цифры и специальные значки. Самый надёжный способ — проверить в самом файле шрифта, какие символы в нём есть. По скриншоту легко не заметить, что русский текст на деле системный.
- **Сервис-воркер.** В коде не должно остаться ни одного упоминания внешних сервисов шрифтов.
